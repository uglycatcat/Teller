# 02 术语表

本文档是 Teller 的权威术语表：每个概念给出精确定义、关键规则，以及「规避清单」（_Avoid_，代表刻意不做的行为）。规避清单与正向需求同等重要，实现时须一并遵守。

> 说明：标注「（本会话增量/修订）」的条目来自 `full-product-refinement` 会话，覆盖或修订了 `docs/history/CONTEXT.md` 的对应定义。

---

## 2.1 内容对象

### 作品（Work）

作者正在创作的一部长篇内容整体，是章节、设定与版本所归属的根对象。其一等结构为**章节**与**设定**，不以「分卷树」或独立「大纲对象」作为产品模型。

- 显示标题存于作品目录元数据（`.teller/work.json` 的 `title`），可与文件夹名不同；缺失时回退为文件夹名。
- 可通过「作品 → 重命名」修改显示标题，并可选同步重命名作品文件夹（失败时保留新标题并提示）。
- 作品 = 本地文件夹（目录即作品），无应用私有黑盒库、无云端唯一真源。

**规避**：项目 / 书 / 文档 / 文件 / 强制分卷树 / 独立大纲实体 / 改标题必须同时成功改文件夹否则禁止 / 标题仅存应用全局库不进作品目录。

### 章节（Chapter）

一部作品中按阅读/写作顺序排列、可单独打开编辑的正文单元。需要分卷或大纲时，用章节命名约定或设定文稿表达，不挂到单独的卷/大纲节点上。

- 侧栏新建时作者只填标题，应用写入带数字前缀的文件名（三位，如 `001-开篇.md`）。
- 侧栏与标签显示的标题以文件名中序号后的标题段为准（`001-开篇.md` →「开篇」），不以文首标题或 frontmatter 为权威。
- 同一作品内章节标题须唯一；新建或重命名冲突时**自动加后缀**（如「番外 2」）。
- 新建章节文稿预填较完整模板（含与标题对应的一级标题、分隔与简短写作提示），作者可改可删；模板支持作品级自定义（见「新建模板」）。
- 排序按文件名数字前缀的**数值**解析（非字符串），超 999 章后位数变化不破坏顺序。
- 每章一个状态标记（见「章节状态」）。

**规避**：篇 / 话 / 文档 / 文件 / episode / 必须从属分卷节点 / 要求作者手写序号文件名 / 以文首 H1 或 YAML frontmatter 为标题权威 / 章节与设定一键互转 / 允许同作品内章节标题重复 / 重名时仅拒绝无自动消解 / 新建章节正文强制空白无模板。

### 设定（Setting）

归属某部作品、供写作时查阅的非正文资料条目；每条设定是一篇可独立打开编辑的文档（人物、世界观、力量体系等均以此承载）。

- 侧栏操作与章节同一套：按标题新建、可拖拽排序、删除进入作品垃圾箱；排序同样以文件名数字前缀落盘（如 `001-主角.md`）。
- 侧栏显示标题同样以文件名中序号后的标题段为准。
- 同一作品内设定标题须唯一；冲突时自动加后缀（如「主角 2」）。
- 新建设定预填设定向模板（标题 + 别名/外形/性格等提示小节，偏资料卡），作者可改可删。

**规避**：笔记 / Wiki / 资料 / 世界书 / lore / 结构化卡片 / 与章节两套不同操作模型 / 设定顺序仅存 UI 不落盘 / 以文首 H1 或 frontmatter 为标题权威 / 章节与设定一键互转 / 允许同作品内设定标题重复 / 重名时仅拒绝 / 新建设定正文强制空白或套章节写作模板。

### 其它文件（Other Files）

作品根目录下、与 `chapters/`、`settings/` 同级的自定义内容（如作者自建的 `reference/` 参考资料目录，及根目录其它松散文件）。

- 侧栏以「其它文件」通用文件树管理这些同级目录与文件。
- 支持在树内新建文件夹/文件（交互参考 VS Code 资源管理器），外部创建后经目录监视刷新。
- 删除其它文件进入**系统回收站**（对齐 VS Code），不进入作品垃圾箱。
- 打开行为：常见图片在应用内预览；常规文本（md/txt/json 等）可编辑；PDF、Word（doc/docx）、Excel 提供**阅读/预览**（非完整办公编辑）；未知类型交系统默认程序或提示无法预览。
- 可将适用的文本文件**移动到章节或设定**（写入对应目录并生成序号文件名，原位置移除）；**不提供**章节/设定降格移回的一键能力。
- 约定写作区（`chapters/`、`settings/`）与元数据区（`.teller`）不作为「其它文件」的主展示对象。

**规避**：只能在系统资源管理器中管理参考资料 / 把 reference 等目录里的 .md 自动并入章节列表 / 禁止用户自建同级目录 / 其它文件树只读不可新建 / 其它文件删除进作品垃圾箱 / 图片/PDF/Office 只能 Reveal 不能应用内阅读 / 把 Word/Excel 做成完整办公套件 / 无法将参考文本升格为章节或设定 / 提供章节/设定一键降格。

### 资源目录（Assets）（本会话新增）

作品根下与 `chapters/`、`settings/` 并列的约定资源目录 `assets/`，存放章节/设定正文引用的本地图片等资源，由 Teller 专用管理。

- 正文用 Markdown 本地相对路径引用（如 `![](../assets/xxx.png)`）。
- 图片纳入快照与导出副本。
- `assets/` 不进「其它文件」通用树。
- 外链图片列为后续增强，非首版必达。

**规避**：图片散落在 chapters/ 内混入二进制 / 图片不进快照导出副本导致迁移丢图 / assets/ 混入其它文件通用树 / 外链图片作为首版必达。

### 新建模板（Work Templates）（本会话新增）

新建章节/设定时预填的模板支持**作品级自定义**：每部作品可有自己的章节模板与设定模板文稿，存作品目录元数据区（`.teller/templates/chapter.md`、`setting.md`）；新建时优先用作品模板，缺省回退内置模板。不做应用级全局模板编辑。

**规避**：模板写死不可自定义 / 只允许应用全局模板 / 作品模板不进作品目录。

### 文稿（Manuscript）

章节或设定条目中可编辑的正文内容；以 Markdown 源码为权威形态与默认编辑视图，可切换预览或分屏预览。

- 支持全量 GFM + 数学公式 + 图表（Mermaid）。

**规避**：富文本文档 / Word 文档 / 纯文本无结构 / 默认所见即所得为唯一编辑方式。

### 作品目录（Work Folder）

磁盘上代表一部作品的本地文件夹；打开某作品即打开该目录作为工作区根。

- 根目录约定包含 `chapters/`（章节）与 `settings/`（设定）；作者可在根下自建同级目录（如 `reference/`、`assets/`）。
- Teller 监视该目录外部变更：无冲突时刷新，有未保存冲突时提示选择保留应用内编辑或加载磁盘版本。
- 提供在系统资源管理器中显示当前文件或作品根目录（Reveal，对齐 VS Code）。
- 打开尚无约定结构的文件夹时，询问是否初始化为作品；确认后写入约定目录再打开。

**规避**：应用私有库 / 云端唯一真源 / 数据库黑盒存储 / 忽略外部改动 / 冲突时静默强制重载 / 无法从应用跳到磁盘位置 / 打开任意文件夹时静默改目录不询问 / 对非作品文件夹只拒绝无初始化选项 / 禁止根目录自建同级资料文件夹。

## 2.2 结构与顺序

### 数字前缀（章节/设定文件名）

章节与设定的顺序由文件名中的数字前缀表达（三位，`001`、`002`…）。拖拽重排时应用改写数字前缀。

- 排序按前缀**数值**解析，而非字符串字典序，避免超 999 章后位数变化乱序。
- 不打开应用也能看懂与恢复顺序；作品目录备份/同步后仍自洽。

**规避**：仅存 UI 不落盘 / 文件名任意 / 前缀位数不固定导致字符串排序错乱。

### 标题权威（Title Authority）

侧栏与标签显示的章节/设定标题，取自文件名中数字前缀之后的标题段（`001-开篇.md` →「开篇」）。**不以**文首 H1 或 YAML frontmatter 作为标题权威（可作为后续增强，非必达）。

### 章节状态（Chapter Status）（本会话新增）

每章一个状态标记，存于章节文稿首部 YAML frontmatter（如 `status: 定稿`），随文件备份与移动。

- 三态：**草稿 / 进行中 / 定稿**。
- frontmatter 仅承载状态等字段，**不**作为标题权威（标题仍以文件名标题段为准）。
- 侧栏与标签可用轻量视觉（图标/颜色点）展示状态。

**规避**：状态塞进文件名后缀导致标题段解析歧义 / 状态存应用全局或集中清单导致与文件脱节 / 以 frontmatter 的 title 替代文件名标题段权威 / 状态值自由标签不收敛。

### frontmatter 字段（本会话新增）

章节文稿首部 YAML frontmatter 支持 `status` 状态字段 + 常用字段（created/updated、字数、标签等）。

- 标题仍以文件名标题段为权威，frontmatter 不承载标题。

**规避**：frontmatter 的 title 取代文件名标题段权威 / 字段无边界任意扩展。

## 2.3 工作区与界面

### 工作区（Workspace）

一个 Teller 窗口所绑定的创作上下文，固定对应一部作品；其内可同时打开多个章节（及设定）进行编辑，并支持编辑器分组分屏（左右与上下，形成网格对照）。

- 左侧资源侧栏以上下可折叠分区承载「章节」「设定」，并另有「其它文件」树。
- 一窗一部作品；可同时存在多个窗口并行编辑**不同**作品。
- 再次打开已在某窗口打开的作品目录，拒绝第二窗并聚焦已有窗口。
- 再次打开某作品时，恢复先前的标签集合、激活标签、侧栏折叠、编辑器分屏布局与 AI 面板开闭等状态。

**规避**：多根工作区 / 单窗挂载多部作品 / 全局单例仅一部作品 / 侧栏顶部分段一次只显示一类 / 同一作品目录多窗并行编辑 / 每次打开作品都重置为空白布局 / 仅多标签不可分屏 / 侧栏无视根目录自建同级资料夹。

### 欢迎页（Welcome）

未打开任何作品时的起始界面，提供新建作品、打开作品目录、最近打开列表，以及可选的 API Key 配置快捷入口（不强制配置即可写作）。

- 新建作品时收集标题与保存位置，并生成约定**空**目录结构（不预置章节或设定文件）。
- 最近打开默认保留约 10 部，支持固定与移除；路径失效时标记并允许重新定位或移除。
- 可通过「作品 → 关闭作品」回到欢迎页（对齐 VS Code 关闭文件夹）；依赖自动保存，仅保存失败时拦截关闭。
- 不支持将文件夹拖入窗口打开。

**规避**：启动即强制打开文件夹对话框 / 无首页直接空白工作区 / 必须先填 Key 才能进入 / 新建时强制填写模板/封面/笔名 / 最近列表无限累加且不可管理 / 关闭作品后留空白工作区不回欢迎页 / 新建时自动插入「第一章」或设定模板文件 / 拖入文件夹作为打开作品方式。

## 2.4 编辑器

### 编辑器排版（Editor Typography）

文稿编辑区的可读性设置：可在应用设置中调整字体家族、字号、行高，以及可选的最大内容宽度；配色随主题。

- 默认开启软换行（可关）；默认显示行号（可关）；小地图默认关闭（可开）。

**规避**：不可调排版 / 稿纸模式 / 竖排 / 默认关闭软换行且强制横向滚动 / 强制无行号且不可开 / 默认开启小地图占宽。

### 编辑器交互（本会话新增）

- 每个编辑器标签有**独立**撤销/重做栈，切换标签不串。
- 标签栏支持拖拽排序。
- 分屏通过拖拽标签到左/右/下边缘触发，右键标签「向右/向下拆分」并存。

**规避**：跨标签全局撤销栈导致回退不可预期 / 标签不可拖拽排序 / 分屏引入分组折叠或仅靠按钮。

### 专注模式（Focus Mode）

写作时一键弱化工作台 chrome：隐藏侧栏等非编辑区域，正文居中版心显示，便于沉浸写作；可退出回到完整三栏工作区。

**规避**：无沉浸写作视图 / 强制始终无侧栏。

## 2.5 AI 能力

### AI 面板（AI Panel）

工作区内与编辑器并排的对话式 AI 区域，用于围绕当前作品提问、续写、改稿等，而不离开写作界面。

- 默认上下文为「当前章节 + 该作品全部设定」；可按需追加引用其他章节及「其它文件」中可抽取文本的资料（@/附加，仿照 Cursor）；不默认塞入整个 `reference/`。
- 每部作品可有多条面板会话（新建、切换、归档/删除），再次打开可回到先前会话。
- 模型输出流式显示；可将回复「插入到光标处」或「应用到选区」（大块变更可预览确认）。
- 提供 **Ask / Agent** 手动切换（对齐 Cursor）。
- 每次回复后显示本次输入/输出 token 用量。

**规避**：独立 AI 页 / 外部聊天网页 / 默认塞入全作品正文 / 每部作品强制仅一条会话 / 每次打开作品会话强制空白 / 仅整段返回无流式 / 面板结果只能手拷 / 自创与 Cursor 冲突的 AI 编辑交互 / 禁止引用其它文件资料 / 默认全量注入 reference / 面板默认无开关即批量改多章 / 按章节强制绑定唯一会话 / 隐藏 token 用量无可感知成本。

### 内联 AI（Inline AI）

在编辑器正文中就地触发的 AI 能力（选中后改写、续写），与 AI 面板互补。

- 触发方式：选中文本后浮现「改写/续写」悬浮工具栏（对齐 Cursor）；自定义快捷键作为并存入口。
- 改稿结果先以预览/对比呈现，接受/拒绝后写入文稿（对齐 Cursor）；生成流式显示；接受后进入正常撤销栈。
- 失败时给出可读错误与重试/去设置引导，不阻断写作；请求可取消。
- 普通内联默认只改当前文稿；跨文稿批量改写须切到 Agent 模式。
- 不提供边输入边出现的幽灵补全（Tab 灰字续写）。

**规避**：仅侧栏对话 / 仅命令面板 / 无预览直接覆盖选区 / AI 失败阻断写作 / 静默失败无引导 / 仅整段返回无流式 / 内联默认静默改写多章 / 打字时灰字自动续写 / 仅右键或仅快捷键触发。

### Agent 模式（Agent Mode）

AI 面板中与 Ask 模式并列、由作者手动切换的工作模式（对齐 Cursor 的 Ask / Agent 切换）。

- Agent 时：允许模型在一轮中提议修改多个章节、设定及已附加资料，以变更集预览后全部或逐条接受/拒绝；可提议**新建/重命名**章节/设定，**不得**提议删除。
- Ask 时：偏问答与单目标协助，不默认批量改写多文稿。
- 界面清晰显示当前模式。

**规避**：默认始终多文件改写无开关 / 多文件改写无预览直接落盘 / 与普通对话混为一体无法区分权限 / 用独立会话类型替代 Ask/Agent 切换 / Agent 默认可删章节/设定 / 结构变更只能人手连新建也不行。

### 写作规则（Writing Rules）

归属某部作品、约束 AI 行为的持久说明（人称、文风、禁词、世界观红线等），以作品目录元数据区规则文稿保存（`.teller/rules.md`），随作品备份与移动。

- 以自然语言为主，新建时提供模板骨架（人称/文风/禁词/红线等引导小节），作者可全删。
- AI 面板、内联 AI 与 Agent 模式默认带上该规则；作者可编辑，可在单次对话中临时关闭应用规则。

**规避**：无作品级持久规则只能每次口述 / 规则只存应用全局不进作品目录 / 规则不可临时关闭 / 用设定条目冒充唯一规则机制却无法默认注入 AI / 强制结构化模板框死 / 纯空白无引导。

### 写作审阅（Writing Review）

内置的审阅技能（类比 Cursor 的 code review skill）：由作者在 AI 对话中手动触发。

- 审阅结果作为**该会话中的消息**返回（可疑点、依据等），不使用独立审阅/Problems 面板。
- 作者随后通过同一对话决定：是否再生成审阅 Markdown 落盘、是否让 AI（含 Agent 模式）按意见修改，或仅参考不改文。
- 审阅本身不自动改文，也不在保存时后台偷跑。

**规避**：独立审阅结果面板作为主呈现 / 保存时自动全盘 lint 扫文 / 审阅结果直接覆盖正文 / 无审阅技能只能口头临时拼提示 / 后台定时偷跑审阅 / 强制每次审阅都落盘 md 或强制自动开改。

### 内置写作技能（Built-in Writing Skills）

产品理想形态提供一组可手动触发的一等 AI 技能（结果均进入当前对话消息，交互范式与 Writing Review 相同），至少包括：

1. 写作审阅
2. 续写本章
3. 改写选区/段落
4. 根据本章草稿更新设定（提议修改，预览后接受）
5. 策划向技能（开大纲/拆章建议、情节节拍检查等）

- 策划向输出是建议文本，不把大纲/细纲提升为与章节并列的一等结构。
- 是否导出 Markdown、是否据此改稿，由作者在对话中决定。
- 经 AI 面板 `/` 菜单唤起。

**规避**：理想形态几乎无命名技能只靠自由聊天 / 策划技能自动创建大纲一等公民 / 技能结果默认绕过对话直接改多文件 / 用独立工具窗替代对话式 skill 输出。

### 作品技能（Work Skills）

归属某部作品的自定义 AI 技能，存放在作品目录元数据区（`.teller/skills/`），随作品备份与移动。

- 作者可手写 skill 文稿，也可在对话中指挥 AI 生成或修改当前作品的 skill；落盘后可与内置技能一样被点名触发，结果进入当前会话消息。
- 唤起方式为 AI 面板输入 `/` 打开技能菜单（列出内置技能与本作品技能）。

**规避**：不可自定义只能用官方技能 / 自定义技能只存应用全局不进作品目录 / 禁止通过对话生成作品技能 / 生成 skill 时绕过作者确认直接覆盖且无预览 / 仅靠自然语言猜测技能且无 / 菜单入口。

### 多模型选择（本会话新增）

模型供给为 BYOK、DeepSeek 默认；应用设置定全局默认模型，每条 AI 会话可临时覆盖切换。

**规避**：会话内不可换模型只能全局唯一 / 每会话强选模型无全局默认。

## 2.6 版本管理

### 快照 / 版本管理（Snapshot / Version Control）（本会话重大修订）

作品在某一时刻的可回看、可恢复的完整状态，升级为**类 git 的版本管理**。

- **commit**：显式创建快照 ≈ git commit（可填备注）；自动保存不产生版本（仅防丢）。
- **branch**：可开分支，用于平行剧情试写与动大改前的安全网；支持 **checkout** 切换分支继续写作。
- **不提供自动 merge**：分支内容由作者手动取舍（选择性复制/应用回主干）——此为与 git 的刻意差异。
- 历史以**树状 DAG 图**可视化（含分支线），并支持快照间 / 快照与当前的文稿 diff。
- 快照范围含 `chapters/`、`settings/` 及根目录其它同级资料（如 `reference/`、`assets/`）；实现须避免把快照库自身递归打进快照。
- 存储采用内容寻址去重（未变文件共享存储），物理存于作品目录元数据区（`.teller/snapshots/`），随作品一并备份与移动。
- 恢复粒度：整作品恢复为必达；单文件恢复列为后续增强。

**规避**：仅备份点无分支 / 分支只读不可 checkout / 自动文本 merge（冲突体验差）/ 无树状历史图看不出分叉 / 版本库存应用全局不随作品走 / 仅盲备份无可读历史 / 快照仅含章节设定而排除同级参考资料 / 快照库递归自包含。

### 垃圾箱（Trash）

作品目录内的暂存删除区；**仅**被删除的章节或设定进入此处。

- 通过菜单「作品 → 垃圾箱」打开管理页（侧栏不设入口），可恢复、立即永久删除、清空。
- 默认保留约 30 天，应用设置可改为 7 / 30 / 90 天或永不自动清除。
- 其它文件的删除不走此垃圾箱（走系统回收站）。

**规避**：仅用系统回收站处理章节/设定删除 / 删除章节/设定即永久抹除 / 应用全局统一垃圾箱 / 侧栏常驻垃圾箱入口 / 其它文件与章节共用作品垃圾箱。

## 2.7 系统与平台

### 应用设置（App Settings）

应用级偏好的统一配置页（主题、垃圾箱保留期、编辑器排版、AI API Key、快捷键等）。

- API Key 存于本机安全存储（系统密钥链/加密存储），不写入作品目录明文文件。
- 界面文案以简体中文为唯一完整支持语言。
- 快捷键有默认方案，可在设置中查看与修改。
- 提供检查更新入口（本会话细化为：更新走手动下载，不做应用内自动更新）。

**规避**：配置分散无统一入口 / Key 明文写进作品文件夹 / 完整形态必达中英双语 / 快捷键写死不可自定义 / 强制更新才能继续使用。

### 作品搜索（Work Search）

在当前作品范围内按关键词检索并定位匹配处；为关键词全文搜索，不做语义搜索。

- 默认搜索范围为章节与设定；可勾选将「其它文件」中可检索文本纳入搜索。
- 查找/替换对齐 VS Code：当前文稿内可查找与替换；作品级批量替换默认仅作用于章节与设定（带结果预览与确认），避免误改参考资料。

**规避**：仅当前标签内查找 / 无搜索 / 语义检索 / 无替换 / 作品级替换无预览直接改写 / 默认强制搜索全部其它文件且批量替换也改参考资料。

### 字数统计（Word Count）

写作过程中的篇幅反馈：状态栏常显当前打开文稿的字数；可通过「作品 → 统计」或状态栏入口查看各章节字数与作品合计。

- 支持两种口径切换：仅汉字，或汉字 + 标点（字符数，对齐网文平台惯例）；统计说明中写清当前口径。
- 侧栏章节标题旁不常驻实时字数。

**规避**：无字数反馈 / 侧栏每章标题旁实时刷字数 / 口径写死不可切换 / 不说明统计口径。

### 崩溃恢复（Crash Recovery）

异常退出后的防丢机制：以短间隔自动保存为主；若仍有未成功落盘的编辑缓冲，下次启动时提示恢复。

**规避**：无任何恢复提示 / 完整多草稿崩溃会话恢复中心为必达。

### 本地优先隐私（Local-First Privacy）

Teller 默认不采集使用遥测；作品正文与 API Key 不上传到 Teller 自有服务器；AI 请求仅发往作者配置的模型供应商；完整形态不要求账号或云同步；理想形态不引入 MCP 或通用外部工具协议。

**规避**：默认遥测 / 正文上传 Teller 服务器 / 强制账号云同步 / 理想形态以 MCP/通用插件协议为必达扩展面。

### 主题（Theme）

应用外观配色方案；默认为深色，可切换浅色，也可设置为跟随操作系统。

**规避**：仅深色不可切换 / 强制唯一浅色。

### 导出（Export）

将文稿输出为便于交稿或外传的文件：

- 可导出当前打开的章节/设定为 Markdown 或纯文本。
- 可将整部作品按章节顺序合并为一个 Markdown 或纯文本（设定可勾选是否并入；参考资料不塞进同一合并文件）；每章以标题开头、章间空行。
- 也可导出为文件夹副本（含 chapters、settings 与同级资料，默认排除快照库以免体积过大）。
- 完整形态不包含 Word/PDF 排版导出或平台一键发布。

**规避**：无导出能力 / Word/PDF 为首版必达 / 平台一键发布 / 合并导出硬塞全部参考资料 / 文件夹副本默认打进全部快照历史。

### 平台与分发（本会话细化）

仅发布 **Windows**（不做 macOS / Linux）；安装包为主形态；更新走作者手动下载覆盖，不引入应用内自动更新。

**规避**：承诺 macOS/Linux 完整支持 / 应用内自动更新强推。
