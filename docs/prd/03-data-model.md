# 03 数据模型

本文档描述 Teller 的底层数据模型：作品目录物理结构、实体关系、文件命名约定、frontmatter 字段、章节状态机，以及类 git 版本库的结构。

---

## 3.1 作品目录物理结构

一部作品 = 一个本地文件夹。约定结构如下（`reference/`、`assets/` 为可选，其余为 Teller 约定）：

```
作品文件夹/
├── chapters/              # 章节文稿（Markdown）
│   ├── 001-开篇.md
│   ├── 002-少年.md
│   └── ...
├── settings/              # 设定文稿（Markdown）
│   ├── 001-主角.md
│   ├── 002-世界观.md
│   └── ...
├── reference/             # 作者自建同级资料（可选，进入「其它文件」树）
├── assets/                # 图片等资源目录（由 Teller 专用管理，不进「其它文件」树）
└── .teller/               # 元数据区（隐藏目录）
    ├── work.json          # 作品显示标题等元数据
    ├── rules.md           # 写作规则
    ├── skills/            # 作品级自定义技能
    ├── sessions/          # AI 面板会话历史
    ├── snapshots/         # 版本库（类 git）
    ├── templates/         # 作品级新建模板（章节/设定）
    └── trash/             # 垃圾箱（删除的章节/设定）
```

设计原则：**目录即作品，自包含可迁移**——标题、规则、技能、AI 会话、版本历史全部存在目录内，拷贝文件夹即带走一切，换机/换路径打开即恢复。

---

## 3.2 实体与关系

| 实体 | 说明 | 关系 |
|---|---|---|
| 作品 Work | 根对象 | 1 — N 章节；1 — N 设定；1 — N 其它文件；1 — 1 元数据区 |
| 章节 Chapter | 正文单元，有序 | 属 1 作品；1 — 1 frontmatter |
| 设定 Setting | 查阅用资料 | 属 1 作品；1 — 1 frontmatter |
| 其它文件 Other Files | 参考资料 | 属 1 作品（根目录同级） |
| 资源 Assets | 正文图片等 | 属 1 作品（`assets/`） |
| 版本库 Snapshot | 版本历史 | 属 1 作品（`.teller/snapshots/`） |
| AI 会话 Session | 对话历史 | 属 1 作品，可多条 |

**一等公民仅章节与设定**，无分卷/大纲实体；卷/大纲用命名约定或设定文稿表达。

---

## 3.3 文件命名约定

- 章节：`NNN-标题.md`（`NNN` 为三位数字前缀，如 `001`、`012`、`999`）。
- 设定：`NNN-标题.md`（同规则）。
- 显示标题 = 文件名中序号后的标题段（`001-开篇.md` →「开篇」）。
- 标题唯一性：同作品内章节标题彼此唯一、设定标题彼此唯一（跨类型可同名）；冲突时自动加后缀（如「番外 2」）。
- 排序：按数字前缀**数值**解析，而非字符串字典序，避免超 999 章后乱序。

---

## 3.4 frontmatter 字段

章节/设定文稿首部可含 YAML frontmatter，支持以下字段（标题**不**走 frontmatter）：

```yaml
---
status: 定稿          # 草稿 | 进行中 | 定稿（章节状态，三态）
created: 2026-08-25   # 创建时间（可选）
updated: 2026-08-25   # 更新时间（可选）
tags: [主线, 战斗]     # 标签（可选）
---
```

约束：frontmatter 不承载标题（标题权威是文件名标题段）；字段集收敛为上述常用字段，不无限扩展。

---

## 3.5 章节状态机

状态三态，存于 frontmatter `status`：

```
草稿 (draft) ──▶ 进行中 (in-progress) ──▶ 定稿 (final)
     ◀──────────────────────────────────────（可双向，无强制流转）
```

- 状态只做「是否还需改」的判断，连载进度靠字数统计表达，不靠状态。
- 侧栏/标签用轻量视觉（图标/颜色点）展示，不阻塞编辑。

---

## 3.6 元数据区文件

| 文件/目录 | 内容 |
|---|---|
| `.teller/work.json` | 作品显示标题（`title` 字段）等元数据；缺失时回退文件夹名 |
| `.teller/rules.md` | 写作规则（自然语言为主 + 模板骨架） |
| `.teller/skills/` | 作品级自定义技能文稿 |
| `.teller/sessions/` | AI 面板多条会话历史（随作品迁移） |
| `.teller/snapshots/` | 版本库（见 3.7） |
| `.teller/templates/` | 作品级新建模板（`chapter.md` / `setting.md`） |
| `.teller/trash/` | 垃圾箱（见 3.8） |

---

## 3.7 版本库数据结构（类 git）

快照升级为类 git 版本管理，物理存 `.teller/snapshots/`，数据结构：

- **commit 对象**：备注（message）、创建时间、内容树引用、父 commit 引用（可多个，形成分支合并点）。
- **branch 引用**：命名分支，指向某个 commit；默认主干（如 `main`）。
- **checkout**：当前工作区 HEAD 指向某个 commit / branch。
- **内容寻址存储**：按文件内容哈希去重，未变文件共享存储，避免全量复制膨胀。
- **历史图**：树状 DAG（含分支线），支持快照间 / 快照与当前的 diff。

边界：
- 显式创建快照 = commit；自动保存**不**产生版本（仅防丢，不污染版本历史）。
- 快照范围含 `chapters/`、`settings/`、`reference/`、`assets/` 等根目录同级资料；**排除** `.teller/snapshots/` 自身（防递归）。
- 恢复粒度：整作品恢复（必达）；单文件恢复（后续增强）。
- **无自动 merge**：分支回并由作者手动取舍。

---

## 3.8 垃圾箱结构

- 仅删除的章节/设定进入 `.teller/trash/`，记录原路径、删除时间。
- 保留期默认 30 天，可配置 7 / 30 / 90 天或永不自动清除。
- 操作：恢复（回原位）、立即永久删除、清空。
- 其它文件的删除不走此垃圾箱（走系统回收站）。

---

## 3.9 状态恢复模型

- 文稿内容：以磁盘自动保存结果为准。
- 工作区状态（标签集合、激活标签、侧栏折叠、分屏布局、AI 面板开闭）：随作品元数据保存，重开恢复。
- AI 会话：按作品保存于 `.teller/sessions/`，重开带回。
- 未落盘缓冲：崩溃后下次启动提示恢复。
