# 01 产品概述

## 1.1 一句话定位

面向长篇创作者的 AI 原生桌面写作工作台。

更本质的隐喻：**专用于小说 / 长文写作场景的 Cursor**——把 Cursor 的「目录 = 代码仓库、文件 = 源码」整套心智，平移为「目录 = 作品、文件 = 章节/设定」。

## 1.2 项目背景（要解决的问题）

小说 / 网文创作通常是 20 万到 100 万字的长文本工程。当前常见工作流存在以下问题：

1. 通用办公软件（Word / WPS）不针对长篇创作场景设计。
2. 写作、章节管理、设定整理、版本管理分散在多个工具中。
3. AI 辅助写作通常要在浏览器与编辑器间反复切换，破坏创作专注。

Teller 的目标是将上述能力集中到一个工作台，降低切换成本，提升持续写作效率。

## 1.3 核心价值

- **少切换**：写作与管理在同一界面完成。
- **可持续**：支持长周期、长篇幅内容生产。
- **易扩展**：为后续 AI 能力预留空间。

## 1.4 目标用户

- 网文作者、小说作者、长篇内容创作者。
- 以 **Windows 桌面软件**创作为主，重视持续产出、稳定保存与专注体验。

## 1.5 核心参考目标

- **VS Code / Cursor / Obsidian 是核心参考目标**。
- UI 交互、信息架构与可扩展性优先参考 VS Code。
- AI 与写作工作区的交互（面板、内联、流式、接受/拒绝、@、Ask/Agent）整体对齐 Cursor。
- 参考仓库：https://github.com/microsoft/vscode.git

## 1.6 产品形态与平台

| 维度 | 决策 |
|---|---|
| 技术框架 | Electron |
| 产出形态 | 桌面应用（不是网页站点） |
| 平台 | **仅 Windows**（不做 macOS / Linux） |
| 分发 | Windows 安装包 |
| 更新 | 手动下载覆盖，不引入应用内自动更新 |
| 界面语言 | 简体中文（唯一完整支持语言） |
| 默认主题 | 深色（可浅色、可跟随系统） |

## 1.7 产品边界（做什么 / 不做什么）

**核心范围**：本地文件夹即作品、章节与设定管理、Markdown 写作、AI 辅助（面板/内联/Agent/技能/规则/审阅）、类 git 版本管理、搜索、字数统计、导出、垃圾箱。

**刻意不做**（完整清单见各模块的「规避清单」）：

- 不做云端账号、云同步、遥测（本地优先隐私）。
- 不做 Word/PDF 排版导出、平台一键发布。
- 不做 MCP / 通用外部工具协议。
- 不做 Tab 幽灵补全（打字时灰字续写）。
- 不做分卷 / 大纲一等公民（保持扁平模型）。
- 不做章节 ↔ 设定一键互转、章节降格为其它文件。
- 不做 macOS / Linux 版本。

## 1.8 开发须知

- 该项目为独立开发者与 AI 协作搭建，开发者主要扮演产品经理角色。
- 使用 Electron 框架；整体前端、UI 交互、美术设计风格优先对齐 VS Code。
