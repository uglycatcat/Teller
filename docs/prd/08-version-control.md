# 08 版本管理（快照 → git）

本文档描述 Teller 的版本管理能力。快照已从「简单备份点」升级为**类 git 的版本管理**，但刻意不照搬 git 的全部语义（详见 8.10）。

---

## 8.1 总览

| git 概念 | Teller 对应 |
|---|---|
| commit | 显式创建快照（可填备注） |
| branch | 分支（平行剧情试写 + 大改安全网） |
| checkout | 切换分支继续写作 |
| log --graph | 树状 DAG 历史图 |
| diff | 快照间 / 快照与当前的文稿对比 |
| 内容寻址存储 | 未变文件哈希去重 |

## 8.2 commit（显式快照）

- 入口：菜单「作品 → 保存快照」（或等价侧栏入口）。
- 创建时可填备注。
- 自动保存**不**产生版本（仅防丢），版本历史由显式 commit 构成。

## 8.3 branch（分支）

- 用途：**平行剧情试写**（「如果主角做了不同选择」的多走向）+ **动大改前的安全网**（改崩了回主干）。
- 支持命名分支；默认主干（如 `main`）。

## 8.4 checkout（切换）

- 可切到某分支，工作区内容切换到该分支状态，继续在其上写作。
- 分支非只读存档。

## 8.5 历史图（树状 DAG）

- 以树状图（含分支线）呈现版本历史，能看清分叉与合并关系。
- 支持快照间 / 快照与当前的文稿 diff。
- 不做无结构的平铺时间线。

## 8.6 diff

- 对章节/设定文稿做可读差异对比（文本为主）。
- 二进制参考资料以「纳入/恢复完整」为准，不做文本级 diff。

## 8.7 存储

- 内容寻址去重：按文件内容哈希，未变文件共享存储，避免全量复制膨胀。
- 物理存 `.teller/snapshots/`，随作品目录备份与移动。
- 快照范围含 `chapters/`、`settings/`、`reference/`、`assets/` 等根目录同级资料；**排除** `.teller/snapshots/` 自身（防递归）。

## 8.8 恢复

- 整作品恢复到某 commit / branch 的完整状态（恢复前确认覆盖当前文件）。
- 单文件恢复列为后续增强。

## 8.9 与自动保存的关系

- 自动保存 = 防丢（短间隔落盘），不产生版本历史。
- 显式快照 = commit，构成可回看、可恢复的版本节点。
- 两者边界不变。

## 8.10 与 git 的刻意差异

| 能力 | Teller 决策 | 理由 |
|---|---|---|
| merge | **不提供自动 merge**，作者手动取舍 | 小说文本是连续散文，自动三方合并冲突率高、体验差 |
| 分支删除保护 | Agent 不得提议删除章节/设定 | 删除仍由作者手动，进垃圾箱 |
| 存储位置 | 版本库存作品目录内（`.teller/snapshots/`） | 保持「目录即作品」自包含可迁移 |

---

## 8.11 迭代说明

- 版本管理为完整形态需求；具体迭代切片（如首版只做显式快照、分支后置）另议，不影响本文档的完整定义。
