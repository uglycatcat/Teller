# 11 非功能需求

本文档描述 Teller 的非功能需求：性能、安全、可靠性与本地优先约束。

---

## 11.1 性能

- 长文本规模：单章数万字、整部作品 20 万–100 万字量级下，编辑器与预览应保持流畅。
- 超长章节：正文编辑与渲染不因单章过长而明显卡顿（具体指标由实现阶段 benchmark 确定）。
- 侧栏长列表：几百章的扁平列表滚动/过滤应流畅（虚拟滚动等）。
- 版本库：内容寻址去重，避免快照全量复制导致磁盘膨胀。
- AI 上下文：超窗时智能裁剪（见 07.6），避免硬失败。

## 11.2 安全

- API Key 存本机安全存储（系统密钥链/加密存储），不明文写入作品目录。
- 无遥测；正文与 Key 不上传 Teller 自有服务器。
- AI 请求仅发往作者配置的模型供应商。

## 11.3 可靠性

- 文稿自动保存（短间隔 + 失焦/切标签），防崩溃/遗忘丢失。
- 崩溃/强退后，启动时提示恢复未落盘编辑缓冲。
- 关闭作品/标签依赖自动保存，仅保存失败时拦截。
- 外部变更监视：无冲突自动刷新，有冲突提示二选一，不静默强载。

## 11.4 本地优先

- 目录即作品：作品文件夹自包含（含标题、规则、技能、会话、版本历史），可备份/迁移。
- 作品在应用外仍自洽（文件名前缀表达顺序、Markdown 纯文本可读）。
- 无强制账号、无云同步、无网络依赖即可写作。

## 11.5 兼容性

- 目标平台仅 Windows（Electron）。
- 文件系统：处理 Windows 文件名字符集；作品标题生成合法文件夹名。
- 编码：统一 UTF-8（Markdown 文稿），实现阶段明确换行约定（LF/CRLF）。
