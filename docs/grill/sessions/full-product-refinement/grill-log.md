## Q71 — 章节状态落点

## Q83 — 快照：对齐 git 的 commit + branch（方向性变更）

- 原题：快照存储策略（全量 / 内容寻址去重 / 增量）
- **用户回答：快照理想情况下对齐 git 的 commit 与 branch 功能**

结论（重大方向变更）：快照从「简单备份点」升级为**类 git 的版本管理**——显式创建快照 ≈ commit（带备注），并引入 **branch（分支）** 能力；存储层采用 git 式内容寻址去重（未变文件共享存储）。此方向**推翻** ADR 0006/0007/0014/0055 及 CONTEXT「快照」定义中 `_Avoid_` 的「版本分支 / Git 提交」立场，合并回根文档时需一并修订。

分支语义见 Q87–Q90。

## Q87 — branch 核心用途

## Q88 — checkout 切换分支

- 推荐：A（支持切换继续写）
- **用户回答：A**

结论：支持 checkout，切到分支后工作区内容切换，可在其上继续写作。

## Q89 — merge

- 推荐：B（手动取舍，不自动 merge）
- **用户回答：B**

结论：**不提供自动 merge**；分支内容由作者手动取舍（选择性复制/应用回主干）。此为与 git 的刻意差异——对齐 commit/branch，不照搬 merge。

- **用户回答：A**

- 推荐：B（Windows 优先，macOS/Linux 尽力）

## Q91 — 章节数字前缀格式

- 推荐：B（四位 `0001`）
- **用户回答：A（三位 `001`）**

结论：三位数字前缀 `001`；排序按数字值解析而非纯字符串，避免超 999 章后位数变化破坏顺序。

## Q92 — 字数计量规则

- 推荐：B（汉字+标点）
- **用户回答：C（可切换）**

结论：字数统计支持两种口径切换——仅汉字 / 汉字+标点（字符数），统计说明写清当前口径。

## Q93 — Markdown 能力边界

- 推荐：B（基础 + GFM 扩展）
- **用户回答：C（全量 GFM + 公式/图表）**

结论：编辑器/预览支持全量 GFM + 数学公式 + 图表（如 Mermaid）。

## Q94 — frontmatter 字段集

- 推荐：A（仅 status）
- **用户回答：B（status + 常用字段）**

结论：frontmatter 支持 `status` + 常用字段（created/updated、字数、标签等）；标题仍以文件名标题段为权威（ADR 0049 不变）。

## Q95 — 分发与更新

- 推荐：A（安装包 + 可选自动更新）
- **用户回答：B（仅安装包，手动更新）**

结论：仅 Windows 安装包；更新走手动下载覆盖，不引入自动更新机制（合并时调整 ADR 0036 表述）。
