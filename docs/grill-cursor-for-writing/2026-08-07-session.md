# Grill：小说场景下的「Cursor」最终形态（进行中）

- 日期：2026-08-07
- 技能：grill-with-docs + domain-modeling
- 目的：在已有 CONTEXT/ADR 之上，把 Teller 钉成「专用于小说/长文写作的 Cursor」的最终产品形态
- 输出目录：本文件夹（与 `docs/grill/` 下其它会话隔离）
- 用户说明：同时进行多场 grill，本场结果不得写入其它 grill 文件

## 已读到的产品骨架（事实，非本场新决策）

- **定位**：面向长篇创作者的 AI 原生 **Electron 桌面**写作工作台；参考 VS Code / Cursor / Obsidian。
- **隐喻**：用户本场明确 —— 本质上希望做成专门用于小说/长文写作场景的「Cursor」。
- **内容模型**：作品 = 本地文件夹；一等公民为章节 + 设定（扁平，无分卷/大纲实体）；另有「其它文件」树；Markdown 源码权威。
- **工作台**：一窗一部作品；左章节/设定/其它文件，中多标签+分屏，右 AI 面板；可专注模式。
- **AI**：面板 + 内联；默认上下文「当前章节 + 全部设定」；可 @ 附加；流式；接受/拒绝对齐 Cursor；BYOK；无 Key 可写。
- **版本与安全**：文稿自动保存；显式快照（含时间线/diff 为完整形态）；作品内垃圾箱（章节/设定）；本地优先无强制云账号。

## 本场讨论焦点

相对「写代码的 Cursor」，小说场景还缺哪些**一等能力**、哪些该刻意不做 —— 用具体功能题推进，避免空泛定位口号。

## 问答

### Q1 — 跨文稿的 Agent 式改动

**问题：** AI 能否一轮提议修改多个章节/设定？

| 选项 | 含义 |
|---|---|
| A. 默认可多文稿提议（预览后接受/拒绝） | 对齐 Cursor Agent 默认能力 |
| B. 默认只动当前打开文稿 | 更安全、更简单 |
| C. 可多文件，但须显式「Agent 模式」 | 平时单文件；单独模式才允许多文件 |

**推荐：** A

**用户回答：** C

**沉淀：** 引入显式 **Agent 模式**：仅在该模式下允许 AI 生成跨章节/设定（及已 @ 资料）的变更集；普通面板/内联默认只作用于当前文稿（或用户明确指定的单一目标）。变更仍须预览后接受/拒绝。

### Q2 — 写作时的 Tab 幽灵补全

**问题：** 是否提供 Cursor 式灰字续写（Tab 接受）？

| 选项 | 含义 |
|---|---|
| A. 要，默认开可关 | 打字时灰字续写 |
| B. 要，默认关 | 能力可选 |
| C. 不要幽灵补全 | 续写仅显式触发（内联/面板） |

**推荐：** B

**用户回答：** C

**沉淀：** 完整形态**不提供**边打字边出的幽灵补全/Tab 灰字续写。续写、改写只通过内联 AI 或 AI 面板（及 Agent 模式）等**显式触发**，避免干扰文风与专注。

---

### Q3 — 作品级写作规则（Rules）

**问题：** 是否提供始终约束 AI 的作品级规则？

| 选项 | 含义 |
|---|---|
| A. 要，作品内规则文稿，AI 默认带上 | 可编辑；对话里可临时关闭应用规则 |
| B. 要，仅 Agent 模式强制带上 | 普通续写/改写不自动带 |
| C. 不要独立规则系统 | 只靠设定与每次说明 |

**推荐：** A

**用户回答：** A

**沉淀：** 每部作品有一份**写作规则**（存于作品目录元数据区，如 `.teller/rules.md`）。AI 面板、内联 AI、Agent 模式**默认注入**该规则；作者可编辑，并可在单次对话中临时关闭「应用规则」。

---

### Q4 — 一致性检查（写作版 Review）

**问题：** 是否提供人设/前后文冲突类检查？

| 选项 | 含义 |
|---|---|
| A. 要，仅手动触发 | 出可疑点列表，不自动改文 |
| B. 要，保存/定时自动跑 | 像 lint 常驻问题面板 |
| C. 不要独立检查功能 | 只靠自己问面板 |

**推荐：** A

**用户回答：** A（类比 Cursor 对代码的 **review**：须**手动触发**）

**沉淀：** 提供手动触发的**写作审阅（Writing Review）**：对照设定、写作规则与指定范围（如本章/若干章）找出可疑矛盾与依据列表；**不自动改文**。作者可再开面板或 Agent 模式处理。不做保存时自动 lint 式扫描。

### Q6 — 写作审阅结果如何呈现（纠正）

助手曾误提「独立审阅面板 / 只落 md」等选项。

**用户纠正：** Writing Review 应与 Cursor 的 review 一样，是**内置 skill**；返回结果应是**对话中的消息**。之后由用户通过对话决定：是否再生成 review Markdown，或直接让 AI 按意见修改。

**沉淀（以用户为准）：**
- Writing Review = 内置技能，手动触发
- 结果 = 当前 AI 会话消息（非独立 Problems/审阅面板）
- 后续 = 用户在对话里选择：仅参考 / 导出 md / 让 AI（可含 Agent 模式）修改
- 审阅本身不自动改文

### Q7 — 内置写作 skill 范围（理想形态）

**问题：** 除 Writing Review 外，还要哪些一等内置 skill？

| 选项 | 含义 |
|---|---|
| A. 小而硬 | Review、续写本章、改写选区、回写设定 |
| B. A + 策划向 | 再加开大纲/拆章建议、情节节拍检查等 |
| C. 几乎不命名 skill | 主要靠自由聊 |

**推荐：** A

**用户回答：** **A 和 B 都要**（讨论的是产品**理想/完整形态**，不是首版切片）

**沉淀：** 理想形态内置写作 skill 至少包括：
1. Writing Review（一致性/质量审阅）
2. 续写本章（按写作规则 + 设定）
3. 改写选区/段落（语气、缩短、扩写等）
4. 根据本章草稿更新设定（提议改 settings，预览后接受）
5. 策划向：开大纲/拆章建议、情节节拍检查等  
以上均为 skill：结果进当前对话消息；不因此引入「大纲」一等公民对象；是否落盘 md、是否改文由作者在对话中决定。

| 选项 | 含义 |
|---|---|
| A. 作品级自定义 skill | 如 `.teller/skills/` |
| B. 应用级 + 作品级 | |
| C. 仅官方内置 | |

**推荐：** A

**用户回答：** A，并明确：**允许在对话中指挥 AI 生成针对当前作品的 skill**（生成后落入作品级 skill 目录，可再点名触发）。

**沉淀：** 理想形态支持**作品级自定义 skill**（存于作品目录，如 `.teller/skills/`）。作者可手写，也可在 AI 对话中让模型起草/迭代该作品专用 skill；落盘后可与内置 skill 一样在对话中触发，输出进消息。

### Q12 — Agent 如何显式开启

**问题：** 多文件改写的「显式」如何表达？

助手曾给开关 / `/agent` / 独立会话类型等选项。

**用户回答：** **与 Cursor 一样，手动切换 Ask 与 Agent 模式。**
